Networking Essentials - Complete Basics

A modern networking reference and learning guide — from fundamentals to advanced topics. Each section builds on the previous: it explains concepts clearly, shows practical commands, highlights real-world behaviors, and warns about common pitfalls.

Networking Fundamentals (Ground Zero)

Start here if you want the shortest path to being productive. Keep these fundamentals in mind while you read the rest.

What is a network?

  • Nodes (hosts, routers, switches) exchange data over links (copper, fiber, radio).
  • Each link has limits: bandwidth (capacity), latency (one‑way delay), jitter (latency variance), loss (drops).
  • Throughput is what you actually transfer; it is bounded by the slowest segment and by protocol behavior (e.g., TCP ramp‑up).

Traffic patterns

  • Unicast: one‑to‑one (most traffic).
  • Broadcast: one‑to‑all on a LAN (IPv4 ARP, DHCP discover).
  • Multicast: one‑to‑many (streaming, routing protocols).
  • Anycast: same IP announced by many nodes; client reaches the “closest” one (e.g., public DNS resolvers).

Links & topologies

  • Duplex: full‑duplex avoids collisions; duplex mismatch causes severe loss/latency.
  • Topologies: star (common for access), leaf‑spine (DC), ring/mesh (resiliency).
  • Media: UTP (Cat5e/6/6A), fiber (SMF/MMF), Wi‑Fi (802.11). Each has its own MTU and error profile.

Fast troubleshooting (host)

# Addresses & links
ip -br a
ip -br link

# Routes (longest‑prefix match decides)
ip -br r
ip route get 8.8.8.8

# Reachability & path insights
ping 1.1.1.1
tracepath example.com

# Sockets & states
ss -tuna | head
Golden rule: troubleshoot layer‑by‑layer. Verify link (L1/2) → addressing & routes (L3) → ports/state (L4) → app behavior (L7).

OSI vs TCP/IP

The OSI (Open Systems Interconnection) model breaks down networking into seven conceptual layers. Each layer provides services to the one above it and relies on the one below it. Understanding them helps pinpoint where network problems or optimizations occur.

6PresentationFormats and secures data for the applicationTLS/SSL, JPEG, MPEG, ASCII, encryption librariesEncryption, compression, and encoding ensure data compatibility and privacy.
5SessionManages dialogs between endpointsTLS session resumption, NetBIOS, RPC, QUIC sessionsKeeps communication alive and synchronized between hosts.

How to Think in Layers (Modern Troubleshooting)

  • L1 – Physical: Check cables, link lights, and Wi‑Fi signal. ethtool or NIC LEDs verify physical link status.
  • L2 – Data Link: Frames and MACs. Detect VLAN mismatches or STP loops. Use ip link or switch port counters.
  • L3 – Network: IP addressing and routing. Validate gateways, subnets, and routes using ip route, ping, traceroute.
  • L4 – Transport: Ports and sessions. Identify blocked ports or handshake failures. Check with ss, nc, tcpdump.
  • L5–L7 – Upper Layers: Application-level behavior. Debug TLS, HTTP, or DNS using curl -v or dig.

Practical Use Cases by Layer

  • L1–L2: Diagnosing Wi-Fi interference or duplex mismatch.
  • L3: Fixing routing or VPN connectivity.
  • L4: Troubleshooting firewalls and port filtering.
  • L7: Debugging API or TLS issues.

Ethernet, MAC, and ARP/ND

Ethernet moves frames inside a local network (LAN). Delivery is based on MAC addresses. IP needs a MAC destination to put a packet on the wire, which is resolved via ARP (IPv4) or NDP (IPv6).

Definitions

  • MAC address: a 48‑bit identifier written as 6 hex bytes (e.g., 00:1C:42:2E:60:4A). The least‑significant bit of the first byte signals unicast (0) vs multicast (1). ff:ff:ff:ff:ff:ff is broadcast.
  • ARP (Address Resolution Protocol, IPv4): asks “Who has IP X.Y.Z.W? Tell me your MAC.” Replies are cached in the ARP table. Supports gratuitous ARP (announce your own mapping) and can be abused by ARP spoofing if L2 isn’t protected.
  • NDP (Neighbor Discovery Protocol, IPv6): a set of ICMPv6 messages — Neighbor Solicitation/Advertisement (IPv6’s ARP), Router Solicitation/Advertisement (gateway + prefix info), and Duplicate Address Detection (DAD).
  • OUI: the first 24 bits of a MAC point to the vendor; useful to spot device types or anomalies.
# Show neighbor cache (ARP or NDP)
ip neigh                    # list IP→MAC entries

# Clear cache and force rediscovery
sudo ip neigh flush all

# Sniff ARP/NDP on an interface (verify resolution on the wire)
sudo tcpdump -n -e -i eth0 '(arp or icmp6)'
Broadcast containment: ARP/NDP and unknown‑unicast floods grow with L2 size. Use VLANs to limit blast radius.

IP Addressing (IPv4 & IPv6)

IP assigns logical addresses and enables routing between networks. A subnet is a group of addresses that share a network prefix. A default gateway is the router a host uses to reach non‑local subnets.

IPv4

  • 32‑bit dotted decimal (e.g., 192.0.2.10).
  • Important ranges: loopback 127.0.0.0/8, link‑local 169.254.0.0/16, private 10/8, 172.16/12, 192.168/16.
  • TTL (time to live): decremented at each router to prevent loops; when it hits 0 the packet is dropped and an ICMP error may be sent back.
  • Fragmentation can happen on routers if DF is not set; MSS influences TCP payload size.

IPv6

  • 128‑bit hexadecimal, zero‑compression allowed (e.g., 2001:db8::1).
  • Address scopes: Global Unicast (2000::/3), Unique Local (fd00::/8 typical), Link‑Local (fe80::/10).
  • Hop Limit: IPv6’s TTL equivalent.
  • SLAAC: hosts self‑assign from Router Advertisements; DHCPv6 is used for options and/or addresses when required.
  • No router‑side fragmentation; oversized packets trigger ICMPv6 Packet Too Big to the sender.
# Inspect interfaces and addresses
ip -br a                     # brief view of IPs per interface

# View routes (longest‑prefix‑match decides which is used)
ip -br r

# See the chosen egress and next hop for a destination
ip route get 8.8.8.8

# IPv6 example
ip -6 route get 2001:4860:4860::8888

ICMP, MTU, MSS, PMTUD

ICMP (Internet Control Message Protocol) carries network diagnostics and error reporting — it’s how the network tells the sender what went wrong.

Quick definitions

  • MTU (Maximum Transmission Unit): the largest payload a link‑layer frame can carry on a single hop. Common Ethernet MTU = 1500; tunnels/VPNs often reduce this (e.g., 1420–1450).
  • MSS (Maximum Segment Size): the maximum TCP payload per segment. Rough rule on Ethernet: MSS ≈ MTU − 20 (IP) − 20 (TCP) = 1460. Options (e.g., TCP timestamps) lower it slightly.
  • PMTUD (Path MTU Discovery): the sender learns the smallest MTU along the path and adjusts packet/TCP sizes. In IPv4 it relies on ICMP “fragmentation needed” (DF set). In IPv6, routers never fragment; they return ICMPv6 Packet Too Big with the usable MTU.

MTU ↔ MSS examples

Link MTUIP hdrTCP hdrTypical MSSNotes

If ICMP is filtered, PMTUD fails → symptoms: TLS stalls, partial loads, API timeouts. On edges, consider MSS clamping so TCP never exceeds the true path size.

Key ICMPv4 Types

  • Echo Request/Reply (8/0) — reachability test (ping).
  • Destination Unreachable (3) — codes include network unreachable, host unreachable, protocol/port unreachable, fragmentation needed.
  • Time Exceeded (11) — TTL expired in transit (used by traceroute/tracepath).
  • Redirect (5) — router advises a better next hop (often disabled).
  • Parameter Problem (12) — header issue detected.

Key ICMPv6 (incl. NDP)

  • Echo Request/Reply (128/129) — reachability test.
  • Packet Too Big (2) — informs sender of MTU for Path MTU Discovery.
  • Time Exceeded (3) — hop limit expired.
  • Parameter Problem (4) — header field error.
  • Neighbor Solicitation/Advertisement — address resolution (like ARP) and DAD.
  • Router Solicitation/Advertisement — prefixes, default gateway, and flags for SLAAC/DHCPv6.
# Reachability & PMTUD checks (IPv4)
ping 8.8.8.8
ping -M do -s 1472 8.8.8.8     # 1472 (payload) + 28 (IP+ICMP) ≈ 1500 MTU with DF

# Path & MTU hints
tracepath example.com

# IPv6 size test; if oversize, expect ICMPv6 Packet Too Big
ping -6 -s 1452 2001:4860:4860::8888

# Adjust interface MTU when the path requires it
sudo ip link set eth0 mtu 1400

TCP vs UDP

Transport layer protocols move application data between sockets (IP + port). TCP prioritizes reliability and ordering; UDP prioritizes low overhead and timeliness.

TCP — What it is and how it flows

  • Connection setup: 3‑way handshake (SYN → SYN‑ACK → ACK).
  • Reliability: sequence numbers, ACKs, retransmissions, selective ACK (SACK).
  • Flow control: the receiver window advertises how much data it can buffer; window scaling allows high‑bandwidth links.
  • Congestion control: sender adapts to loss/latency to avoid overloading the path.
  • Close: FIN/ACK graceful teardown or RST for abrupt close.
  • Examples: HTTP(S), SSH, databases.
# Watch the handshake and flags on the wire
sudo tcpdump -n -i eth0 'tcp[tcpflags] & (tcp-syn|tcp-ack|tcp-fin|tcp-rst) != 0'

# List established TCP sessions
ss -t state established | head

# Test TCP port reachability
nc -vz example.com 443

UDP — Simple and fast

  • No handshake, no retransmission or ordering by default.
  • Application handles loss if it matters.
  • Examples: DNS, VoIP, game traffic, streaming; QUIC (used by HTTP/3) builds reliability and encryption over UDP.
# Test UDP port reachability
nc -vzu example.com 53

VLANs, Trunks & Spanning Tree

VLAN: a logical Layer‑2 segment. Trunk: a link carrying multiple VLANs via 802.1Q tags. Spanning Tree: prevents loops by blocking redundant paths.

Concepts

  • Access port: sends/receives untagged frames for a single VLAN.
  • Trunk port: carries tagged frames for many VLANs; avoid permissive native VLANs.
  • STP/RSTP/MST: elects a root bridge; ports take roles (root, designated, alternate) to avoid loops.
  • LACP (802.3ad): bundles links into one logical interface for throughput and redundancy.
# Create VLAN 20 sub‑interface on a host
sudo ip link add link eth0 name eth0.20 type vlan id 20

# Assign an IP inside the VLAN
sudo ip addr add 192.168.20.1/24 dev eth0.20

# Enable the interface
sudo ip link set eth0.20 up
Tip: keep VLAN allow‑lists symmetric on trunks across switches to prevent orphan VLANs and blackholes.

DHCP (DORA)

DHCP automatically assigns IP configuration. A lease includes address, mask/prefix, default gateway, DNS, and more. Reservations tie a MAC to a fixed address. Relay forwards requests across subnets.

  • Discover — client broadcasts to find a server. Source IP 0.0.0.0, dest 255.255.255.255 (or via relay).
  • Offer — server proposes a lease (IP + options) and holds it temporarily.
  • Request — client asks to use the offered address (can include server identifier).
  • Acknowledge — server confirms; client configures address and starts the lease timers (T1/T2).
Renewal is unicast Request/ACK to the original server at T1; at T2, the client retries with broadcast if needed. Declines happen if Duplicate Address Detection fails.
# Release and request a lease on interface eth0
sudo dhclient -r eth0

sudo dhclient eth0

# Inspect logs for DORA messages
journalctl -b | grep -i dhcp
Common options (numbers)

3 = router (gateway), 6 = DNS servers, 15 = DNS domain, 42 = NTP, 119 = domain search list.

Routing (Static & Dynamic)

Routing chooses the next hop using longest‑prefix match. The forwarding table (FIB) is programmed from routing decisions (RIB). Policies can steer traffic based on source/interface.

Static & Policy

# Show routes
ip route show

# Default route (send non‑local traffic to the gateway)
sudo ip route add default via 192.168.1.1

# Specific subnet via another router
sudo ip route add 10.20.0.0/16 via 192.168.1.254

# Policy routing: use a separate table for traffic from a source IP
printf "200 app\n" | sudo tee -a /etc/iproute2/rt_tables

sudo ip rule add from 10.0.0.10/32 table app

sudo ip route add default via 10.0.0.1 dev eth1 table app

Dynamic (overview)

  • OSPF: link‑state, areas for scale, cost metric, fast convergence.
  • BGP: policy‑driven between autonomous systems; attributes like local‑pref, MED, AS‑path influence selection; supports ECMP.
For labs, routing daemons (e.g., FRRouting or Bird) expose CLIs (vtysh, birdc) to inspect neighbors and routes.

sudo sysctl -w net.ipv4.ip_forward=1

sudo nft add rule ip nat prerouting  ip daddr 203.0.113.50 dnat to 192.168.1.50
sudo nft add rule ip nat postrouting ip saddr 192.168.1.50 snat to 203.0.113.50

DNS translates names to data (addresses, mail servers, service records). A recursive resolver walks the hierarchy on behalf of clients and caches responses per TTL. Authoritative servers answer for zones they host.

 dig +short A example.com          # IPv4

 dig +short AAAA example.com       # IPv6

 dig MX example.com                # mail exchangers

Split‑horizon DNS: internal and external clients receive different answers by design. Also consider negative caching (NXDOMAIN) which is controlled by TTLs too.

Security: ACLs, Stateful Firewalls, Security Groups, Zero‑Trust

ACLs match on IPs/ports and permit or deny. Stateful engines track connection state to allow return traffic automatically. Security Groups apply per interface in clouds. Zero‑Trust focuses on identity of user/device and least‑privilege network access.

# Baseline host firewall policy
sudo nft add table inet filter

sudo nft 'add chain inet filter input { type filter hook input priority 0; policy drop; }'

# Allow established/related
sudo nft add rule inet filter input ct state established,related accept

# Allow SSH only from an admin subnet
sudo nft add rule inet filter input tcp dport 22 ip saddr 203.0.113.0/24 accept

VPN (IPsec, TLS, WireGuard)

VPNs create encrypted tunnels across untrusted networks. IPsec (IKEv2 + ESP) integrates with many devices; TLS‑based VPNs are flexible; WireGuard is minimal and fast.

# WireGuard client (example)
[Interface]
Address = 10.6.0.2/32
PrivateKey = <client-priv>
DNS = 1.1.1.1

[Peer]
PublicKey = <server-pub>
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = vpn.example.com:51820
PersistentKeepalive = 25
Behind NAT? Permit/forward UDP/51820 (WireGuard) or UDP/500,4500 (IKEv2). If MTU is smaller on the path, clamp TCP MSS on the edge to avoid PMTUD issues.

Wireshark & tcpdump

Packet capture proves or disproves hypotheses. Capture filters limit what you record; display filters narrow what you view.

# Capture to a file for later analysis
sudo tcpdump -i eth0 -n -w trace.pcapng 'port 80 or port 443'

# Open in Wireshark (GUI)
wireshark trace.pcapng &

# Display filters (Wireshark)
http && tcp.flags.syn == 1

(dns.flags.response == 1) && dns.qry.name == "example.com"

tcp.analysis.retransmission || tcp.analysis.lost_segment

ssl || tls || quic
Workflow: reproduce → capture with timestamps → apply filters → validate → write down what changed and why.
