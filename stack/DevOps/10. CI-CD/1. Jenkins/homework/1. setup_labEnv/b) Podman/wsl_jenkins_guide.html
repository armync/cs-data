Jenkins with Podman in WSL

Complete Step-by-Step Guide

Prerequisites

Before starting, ensure you have:

  • Windows 10/11 with WSL2 enabled
  • Ubuntu or Debian-based WSL distribution
  • Podman installed in WSL
  • Basic terminal/command line knowledge

Step 1: Verify Your Environment

1 Open WSL Terminal

Open your WSL terminal (Ubuntu, Debian, etc.)

2 Check Podman Installation 
# Verify Podman is installed
podman --version

# If not installed, install it:
sudo apt update
sudo apt install -y podman podman-compose

Step 2: Create Project Directory

# Create and navigate to project folder
mkdir -p ~/jenkins-podman
cd ~/jenkins-podman

Step 3: Generate SSH Keys

1 Generate SSH Key Pair in PEM Format 
# Generate RSA key in PEM format (compatible with Jenkins)
ssh-keygen -t rsa -b 2048 -m PEM -f jenkins_agent_key -N "" -C "jenkins@node"
Important: The -m PEM flag is required for Jenkins compatibility

This creates two files:

  • jenkins_agent_key - Private key (keep secret)
  • jenkins_agent_key.pub - Public key (safe to share)
2 Verify Key Format 
# Check the private key format
head -1 jenkins_agent_key
The first line should show: -----BEGIN RSA PRIVATE KEY-----
The public key should start with ssh-rsa and end with jenkins@node

Step 4: Create Environment File

Create .env File with Public Key 
# Create .env file with the PUBLIC key
echo -n "SSH_PUBLIC_KEY=" > .env
cat jenkins_agent_key.pub >> .env

# Verify it's correct
cat .env
Important: Make sure you use the PUBLIC key (.pub file), NOT the private key!

Step 5: Create Docker Compose File

Create docker-compose.yml 
nano docker-compose.yml

Paste this content:

version: '3.8'

services:
  jenkinsmain:
    image: docker.io/jenkins/jenkins:lts
    container_name: jenkinsmain
    hostname: jenkinsmain.local
    ports:
      - "8080:8080"
      - "50000:50000"
    volumes:
      - jenkins_home:/var/jenkins_home:Z
    mem_limit: 1536m
    cpus: 2
    restart: unless-stopped
    networks:
      - jenkins_net

  jenkinsnode1:
    image: docker.io/jenkins/ssh-agent:latest
    container_name: jenkinsnode1
    hostname: node1.local
    environment:
      - JENKINS_AGENT_SSH_PUBKEY=${SSH_PUBLIC_KEY}
    mem_limit: 512m
    cpus: 1
    restart: unless-stopped
    networks:
      - jenkins_net

networks:
  jenkins_net:
    driver: bridge

volumes:
  jenkins_home:

Save and exit (Ctrl+X, then Y, then Enter)

Step 6: Start Jenkins Containers

1 Start with Podman Compose 
# Start all containers in detached mode
podman-compose up -d
2 Verify Containers are Running 
# Check container status
podman ps
You should see two containers: jenkinsmain and jenkinsnode1
3 Wait for Jenkins to Initialize 
# Wait about 30 seconds, then get the initial password
sleep 30
podman exec jenkinsmain cat /var/jenkins_home/secrets/initialAdminPassword
Copy this password - you'll need it to unlock Jenkins!
4 Get Jenkins Node Hostname 
# Verify the node hostname
podman exec jenkinsnode1 hostname
You'll use the hostname jenkinsnode1 (not IP) when configuring the Jenkins node. This ensures the connection remains stable even if container IPs change.

Step 7: Access Jenkins Web Interface

1 Open Jenkins in Browser

Navigate to: http://localhost:8080

2 Unlock Jenkins
  • Paste the initial admin password you got earlier
  • Click "Continue"
3 Install Suggested Plugins
  • Click "Install suggested plugins"
  • Wait for installation to complete (2-5 minutes)
4 Create First Admin User
  • Username: admin (or your choice)
  • Password: (your choice)
  • Full name: Your name
  • Email: Your email
  • Click "Save and Continue"
5 Instance Configuration
  • Keep the default URL: http://localhost:8080
  • Click "Save and Finish"
  • Click "Start using Jenkins"

Step 8: Configure Jenkins Node

1 Navigate to Nodes
  • Click "Manage Jenkins" (left sidebar)
  • Click "Nodes" or "Manage Nodes and Clouds"
2 Create New Node
  • Click "New Node"
  • Node name: jenkinsnode1
  • Type: "Permanent Agent"
  • Click "Create"
3 Configure Node Settings

Fill in these values:

  • Number of executors: 1
  • Remote root directory: /home/jenkins
  • Labels: node1 linux
  • Usage: Use this node as much as possible
  • Launch method: Launch agents via SSH
  • Host: jenkinsnode1
Important: Use the hostname jenkinsnode1 instead of an IP address. This prevents connection issues when containers restart.
4 Add SSH Credentials

Click "Add" next to Credentials dropdown, then "Jenkins":

  • Kind: SSH Username with private key
  • Scope: Global
  • ID: jenkins-node1-key
  • Description: Jenkins Node 1 SSH Key
  • Username: jenkins
  • Private Key: Select "Enter directly"

Now get your private key from WSL:

# In WSL terminal
cat ~/jenkins-podman/jenkins_agent_key
Copy the ENTIRE output including:
-----BEGIN RSA PRIVATE KEY-----
and
-----END RSA PRIVATE KEY-----

Make sure there are NO extra spaces or blank lines at the beginning or end.

Paste it into the "Key" text box in Jenkins

  • Host Key Verification Strategy: Non verifying Verification Strategy
  • Click "Add"
  • Select the credential you just created from the dropdown
  • Click "Save"

Step 9: Launch the Agent

1 Start the Connection
  • Click on "jenkinsnode1" in the nodes list
  • Click "Launch agent"
  • Wait 5-10 seconds
  • Refresh the page
You should see: "Agent successfully connected and online"

Step 10: Verify SSH Connection (Optional)

1 Test SSH from Jenkins Main to Node 
# Enter the Jenkins main container
podman exec -it jenkinsmain bash

# Create temporary key file
cat > /tmp/testkey << 'EOF'
# Paste your private key here: cat ~/jenkins-podman/jenkins_agent_key
EOF

chmod 600 /tmp/testkey

# Test SSH connection using hostname
ssh -i /tmp/testkey -o StrictHostKeyChecking=no jenkins@jenkinsnode1

# If successful, you'll get a shell prompt on the node
# Type 'exit' to return to main container, then 'exit' again to return to WSL
exit
If SSH works, the Jenkins agent connection will work too!

Step 11: Test Your Setup with a Job

1 Create a Test Job
  • Go to Jenkins Dashboard
  • Click "New Item"
  • Name: test-node
  • Type: "Freestyle project"
  • Click "OK"
2 Configure the Job

Under "General":

  • Check "Restrict where this project can be run"
  • Label Expression: node1

Under "Build Steps":

  • Click "Add build step"
  • Select "Execute shell"
  • Enter this command:
echo "=== Node Information ==="
echo "Hostname: $(hostname)"
echo "IP Address: $(hostname -I)"
echo "User: $(whoami)"
echo "Working Directory: $(pwd)"
uname -a
  • Click "Save"
3 Run the Job
  • Click "Build Now"
  • Wait for the build to complete
  • Click on the build number (e.g., "#1")
  • Click "Console Output"
The console output should show the job ran on node1.local!

Useful Commands

Container Management

# View running containers
podman ps

# View all containers (including stopped)
podman ps -a

# View container logs
podman logs jenkinsmain
podman logs jenkinsnode1

# Follow logs in real-time
podman logs -f jenkinsmain

# Restart a container
podman restart jenkinsmain

# Stop all containers
podman-compose down

# Stop and remove volumes (fresh start)
podman-compose down
podman volume rm jenkins-podman_jenkins_home

Access Containers

# Execute command in container
podman exec jenkinsmain ls -la /var/jenkins_home

# Open interactive shell
podman exec -it jenkinsmain bash

# Check Jenkins version
podman exec jenkinsmain java -jar /usr/share/jenkins/jenkins.war --version

Network Management

# List networks
podman network ls

# Inspect network
podman network inspect jenkins-podman_jenkins_net

# Get container IP
podman inspect jenkinsnode1 | grep IPAddress

Troubleshooting

Containers Won't Start

# Check logs for errors
podman logs jenkinsmain
podman logs jenkinsnode1

# Check if ports are already in use
sudo netstat -tlnp | grep :8080

# Remove and recreate containers
podman-compose down
podman-compose up -d

Can't Access Jenkins on localhost:8080

# Check if Jenkins is running
podman ps | grep jenkinsmain

# Check port binding
podman port jenkinsmain

# Test from within WSL
curl http://localhost:8080

# Get WSL IP (access from Windows)
ip addr show eth0 | grep inet

Agent Won't Connect

Error: "PEM problem: it is of unknown type"

The SSH key is in the wrong format. Regenerate with PEM format:

cd ~/jenkins-podman
rm jenkins_agent_key jenkins_agent_key.pub .env
ssh-keygen -t rsa -b 2048 -m PEM -f jenkins_agent_key -N "" -C "jenkins@node"
echo -n "SSH_PUBLIC_KEY=" > .env
cat jenkins_agent_key.pub >> .env
podman-compose down
podman-compose up -d

Then update the credentials in Jenkins with the new private key.

Error: "No route to host" or wrong IP

Use the hostname instead of IP address:

  • In Jenkins node configuration, set Host to: jenkinsnode1
  • This prevents connection issues when container IPs change

General connection issues:

Check these common issues:

  • Verify you used the private key (not public) in Jenkins credentials
  • Verify the key starts with -----BEGIN RSA PRIVATE KEY-----
  • Verify no extra spaces or blank lines in the key
  • Check if containers can communicate:
# Test container connectivity
podman exec jenkinsmain getent hosts jenkinsnode1

Reset Everything

# Complete reset (WARNING: deletes all data)
cd ~/jenkins-podman
podman-compose down
podman volume rm jenkins-podman_jenkins_home
podman network rm jenkins-podman_jenkins_net
rm -f .env

# Then start from Step 3 again
