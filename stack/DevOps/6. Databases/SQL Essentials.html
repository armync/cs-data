Introduction to Databases

Databases are structured systems designed to store, organize, and retrieve data efficiently. They are crucial for maintaining consistency, ensuring availability, and managing concurrent access to data across multiple users or applications.

Databases can be categorized based on their structure, query language, and scaling approach. The two most common types are Relational Databases and NoSQL Databases.

SQL vs NoSQL

SQL (Structured Query Language) databases use tables, rows, and columns to store structured data. They are ideal when you need transactions, consistency, and strong data relationships.

NoSQL (Not Only SQL) databases, on the other hand, use more flexible storage models such as documents, key-value pairs, wide columns, or graphs. They are ideal for scalability, performance, and handling semi-structured or unstructured data.

When to Use SQL:

  • Applications with complex relationships (e.g., e-commerce, banking).
  • Where ACID (Atomicity, Consistency, Isolation, Durability) compliance is crucial.
  • When data integrity and strict schema enforcement are required.

When to Use NoSQL:

  • Applications that handle large volumes of unstructured or changing data (e.g., social networks, analytics).
  • Systems that need horizontal scaling across many servers.
  • When flexible schema design and faster reads/writes are preferred over strict transactions.
-- SQL Example: Selecting data
SELECT name, email FROM customers WHERE country = 'USA';

# NoSQL Example: MongoDB Query
db.customers.find({ country: 'USA' }, { name: 1, email: 1 });

Relational Databases (PostgreSQL, MySQL)

Relational databases organize data into tables with predefined schemas. They rely on SQL to define, manipulate, and query data. The two most popular open-source relational databases are PostgreSQL and MySQL.

PostgreSQL Highlights:

  • Supports advanced features such as JSONB data type, window functions, and full-text search.
  • Uses MVCC (Multi-Version Concurrency Control) to manage concurrent transactions efficiently.
  • Supports extensions like PostGIS for geospatial queries.
-- PostgreSQL Table Creation
CREATE TABLE employees (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  department VARCHAR(50),
  hire_date DATE DEFAULT CURRENT_DATE
);

-- Example Query
SELECT name, department FROM employees WHERE department = 'IT';

MySQL Highlights:

  • Highly efficient for read-heavy workloads.
  • Supports different storage engines like InnoDB (transactional) and MyISAM (non-transactional).
  • Easy to replicate using Master-Slave replication.
-- MySQL Table Creation
CREATE TABLE employees (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  department VARCHAR(50),
  hire_date DATE DEFAULT CURRENT_DATE
);

-- Example Query
SELECT * FROM employees WHERE hire_date > '2023-01-01';

NoSQL Databases (MongoDB, Redis)

NoSQL databases prioritize flexibility and performance. They allow developers to store data without predefined schemas, which is ideal for rapidly changing applications or high-traffic systems.

MongoDB (Document Store)

  • Stores data in BSON documents (binary JSON), allowing nested structures.
  • Each document can have a unique structure—no strict schema required.
  • Supports horizontal scaling using sharding.
# Insert a document
db.users.insertOne({ name: 'John', email: 'john@example.com', roles: ['admin', 'editor'] });

# Query documents
db.users.find({ roles: 'admin' });

# Update document
db.users.updateOne({ name: 'John' }, { $set: { email: 'newjohn@example.com' } });

Redis (Key-Value Store)

  • Data stored in memory, offering extremely fast read/write operations.
  • Supports data structures such as strings, lists, sets, and hashes.
  • Commonly used for caching, session management, and real-time analytics.
# Redis Usage
SET user:1 "John Doe"
GET user:1

# Lists
LPUSH tasks "task1"
RPUSH tasks "task2"
LRANGE tasks 0 -1

CRUD Operations (Create, Read, Update, Delete)

CRUD operations form the backbone of database interactions. Below are examples using SQL and NoSQL commands.

-- SQL CRUD Example
CREATE TABLE products (id SERIAL PRIMARY KEY, name TEXT, price DECIMAL);
INSERT INTO products (name, price) VALUES ('Laptop', 1200);
SELECT * FROM products;
UPDATE products SET price = 1100 WHERE name = 'Laptop';
DELETE FROM products WHERE name = 'Laptop';

# MongoDB CRUD Example
db.products.insertOne({ name: 'Laptop', price: 1200 });
db.products.find();
db.products.updateOne({ name: 'Laptop' }, { $set: { price: 1100 } });
db.products.deleteOne({ name: 'Laptop' });

Indexing and Performance Optimization

Indexes help speed up data retrieval operations. However, they increase storage usage and can slow down write operations. Always index columns used in WHERE, JOIN, and ORDER BY clauses.

-- SQL Index Example
CREATE INDEX idx_email ON users(email);
EXPLAIN ANALYZE SELECT * FROM users WHERE email='user@example.com';

# MongoDB Index Example
db.users.createIndex({ email: 1 });
db.users.find({ email: 'user@example.com' }).explain('executionStats');

Backup and Recovery Strategies

Data loss can occur due to system crashes, corruption, or user error. A good backup plan ensures data can be restored quickly with minimal loss.

  • Full Backup: Copy entire database content.
  • Incremental Backup: Only saves changes since the last backup.
  • Point-In-Time Recovery: Restores the database to a specific moment.
# PostgreSQL Backup
pg_dump mydb > backup.sql

# MySQL Backup
mysqldump -u root -p mydb > backup.sql

# MongoDB Backup
mongodump --db mydb --out /backups

Database Replication and High Availability

Replication ensures continuous availability by keeping multiple copies of the database synchronized. High availability (HA) setups minimize downtime in case of failures.

  • Master-Replica: Primary node handles writes, replicas handle reads.
  • Multi-Master: All nodes accept writes (useful for distributed systems).
  • Failover: Automatic switch to standby instance when the main node fails.
# MySQL Replication Example
CHANGE MASTER TO MASTER_HOST='primary', MASTER_USER='replica', MASTER_PASSWORD='password';
START SLAVE;

# PostgreSQL Streaming Replication
primary_conninfo = 'host=primary user=replica password=secret'

Cloud-Based Database Services

Cloud-managed databases simplify scaling, maintenance, and reliability. They provide built-in backups, monitoring, and replication.

AWS

  • Amazon RDS: Managed MySQL, PostgreSQL, and SQL Server with automatic backups.
  • Amazon Aurora: High-performance compatible with MySQL and PostgreSQL.

Azure

  • Azure SQL Database: Fully managed SQL Server in the cloud.
  • Azure Database for PostgreSQL: Offers zone-redundant HA and scaling.

Google Cloud

  • Cloud SQL: Managed PostgreSQL, MySQL, and SQL Server.
  • Cloud Spanner: Global-scale relational database with strong consistency.
