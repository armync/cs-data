Setting up PostgreSQL on Fedora Server (VMware) with Windows Client Access

A step-by-step guide for installing PostgreSQL on a Fedora Server VM, enabling network access, and connecting from a Windows client such as DataGrip.

1) Install and start PostgreSQL on Fedora

Install the server and client utilities:

sudo dnf install -y postgresql-server postgresql-contrib
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

Verify that the service is running:

sudo systemctl status postgresql

2) Verify local access

Fedora uses peer authentication for local Unix socket access. The system user postgres can connect to the database without a password if the Linux username matches the PostgreSQL role.

sudo -u postgres psql
\conninfo
\q

3) Enable network connections

Edit postgresql.conf (usually in /var/lib/pgsql/<version>/data/) and allow PostgreSQL to listen for TCP connections:

listen_addresses = '*'
port = 5432

Restart the service:

sudo systemctl restart postgresql

Check that it is listening externally:

sudo ss -ltnp | grep 5432

4) Authentication: peer, ident, and scram-sha-256

Peer and ident authentication do not use passwords. They simply check if your operating system username matches the PostgreSQL user you are trying to log in as. This works only for local or same-machine logins.

When connecting from Windows or another system, PostgreSQL cannot verify your OS username. That is why password-based authentication is required. scram-sha-256 is the secure, modern method that replaces older md5. It stores passwords in a hashed form and verifies them through a challenge-response process, so the real password is never sent over the network.

5) Create a database user with a password

Create a role for remote access:

sudo -u postgres psql
CREATE ROLE dg_user WITH LOGIN PASSWORD 'strong_password';
-- Optionally:
-- CREATE DATABASE mydb OWNER dg_user;
\q

6) Configure pg_hba.conf for remote access

Edit /var/lib/pgsql/<version>/data/pg_hba.conf and add your Windows machine’s IP address. This file controls who can connect and how.

# Allow Windows client at specific IP
host    all     all     192.168.25.1/32     scram-sha-256

# Local Unix socket
local   all     all                          peer

# Localhost
host    all     all     127.0.0.1/32         ident
host    all     all     ::1/128              ident

Reload PostgreSQL:

sudo systemctl reload postgresql

If you see an error such as “no pg_hba.conf entry for host…”, add a rule matching the client IP shown in the message. Use a subnet like 192.168.25.0/24 while testing, then narrow to /32.

7) Open the firewall

Allow incoming connections on port 5432:

sudo firewall-cmd --add-service=postgresql --permanent
sudo firewall-cmd --reload

8) Find the correct IP addresses

On Fedora (server)

ip addr | grep 'inet '

Use the IP address of the network adapter connected to VMware. Enter this IP as the host in your Windows client.

On Windows (client)

ipconfig

Locate your active adapter’s IPv4 address and ensure this address is listed in pg_hba.conf.

9) Networking in VMware

  • Bridged: VM and host share the same LAN. Other devices can connect.
  • NAT: VM connects through the host’s network. The Windows host can reach the VM.
  • Host-only: Only the host communicates with the VM.

For most development setups, NAT or Bridged mode works fine.

10) Connect from DataGrip on Windows

  1. Open DataGrip and add a new PostgreSQL data source.
  2. Set:
    • Host: Fedora VM’s IP (not localhost)
    • Port: 5432
    • User: dg_user or postgres
    • Password: the password you created
    • Database: postgres or your own
  3. Click “Test Connection” to verify access.
Note: “localhost” in DataGrip refers to your Windows PC, not the Fedora VM. Always use the VM’s IP address.

11) Troubleshooting in context

Connection refused

sudo systemctl status postgresql
sudo ss -ltnp | grep 5432

If it only shows 127.0.0.1:5432, adjust listen_addresses in postgresql.conf.

Ident or peer authentication failed

This means PostgreSQL tried to match your OS username instead of checking a password. Make sure your remote rule uses scram-sha-256.

No pg_hba.conf entry for host

Check which IP address appears in the error, then add or adjust that address in pg_hba.conf and reload the service.

See configuration and logs

sudo -u postgres psql -tAc "SHOW hba_file; SHOW config_file; SHOW data_directory; SHOW listen_addresses;"
sudo journalctl -u postgresql -n 200 --no-pager
