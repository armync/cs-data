    7. Cloud Fundamentals (5 days)  

    Introduction

    • Understand Cloud vs On-Premises
      What changes when you move from traditional infrastructure to cloud: ownership, flexibility, and responsibility.

    • Learn the Cloud Operating Model
      Concepts like on-demand resources, managed services, APIs over hardware, and scaling as a default - not a luxury.

    • Know the Cost of Ownership
      Understand pay-as-you-go pricing, egress costs, and how unused resources still cost money. The cloud makes spinning up easy - but cleaning up is your job.

    • Grasp the Shared Responsibility Model
      Security is not outsourced. Learn what the provider secures (e.g. hardware) and what you own (e.g. identity, data, access).

    • Think Security First
      Cloud doesn’t remove security concerns - it shifts them. Understand the shared responsibility model and why identity, network boundaries, and encryption matter early.

    • Logging Isn’t Free
      Monitoring and logs come at a price - understand log retention, volume, and the trade-offs between observability and cost.

    • Recognise the Limits of Abstraction
      Just because it’s "managed" doesn’t mean it’s magic. Downtime, misconfigurations, and billing surprises still happen - know where to look.

    12. Monitoring & Logging (3 days)

    Introduction:

    • Why Observability Matters
      If you can’t see it, you can’t fix it. Observability helps teams understand system health—from outages and latency to unexpected cost spikes.
    • Monitoring ≠ Observability
      Monitoring tells you something’s wrong. Observability helps you understand _why_. It’s about connecting metrics, logs, and traces for deep insight.
    • Metrics Are the Pulse
      Time-series data lets you track service behavior over time. Prometheus powers alerts and dashboards that keep you informed in real-time.
    • Visualize with Grafana
      Grafana makes data visible and actionable. Build dashboards, set alerts, and use templating to stay ahead of issues.
    • Logs Are the Narrative
      Structured logging tells the story of what happened. Centralizing logs with ELK or Loki helps you trace events fast.
    • Traces Show the Timeline
      Traces let you follow a request through microservices. Use Jaeger and OpenTelemetry to find where things break.
    • Define What “Good” Looks Like
      SLOs, SLIs, and SLAs give reliability structure. Set user-impact-driven targets and measure against them.
    • Don’t Drown in Data
      Not all data is useful. Learn how to manage cardinality, sampling, noise, and cost.
    • Secure Your Telemetry
      Observability needs to be compliant too. Use audit logs, secure pipelines, and protect sensitive data.

    Day-2 Operations

    1. Practical integration of previously learned material

    Learners will demonstrate their ability to integrate and apply all concepts covered throughout the program by designing, deploying, and operating a production-grade three-tier application (frontend, backend, and database).
    This exercise requires combining skills in Linux, networking, Git, databases, cloud fundamentals, infrastructure as code, containers, CI/CD, Kubernetes, monitoring, and security.
    The goal is to validate not only technical proficiency in each domain, but also the capability to bring them together into a cohesive, reliable, and observable system aligned with real-world DevOps practices.

    Task
    Lookup a 3-tier application stack (frontend, backend, database) on GitHub and deploy it as a production-ready solution.

    Requirements

    • Ensure the application flow works end-to-end: a request from the frontend passes through the backend and is stored in the database.

    • Document setup, deployment, and usage in a README (Markdown).

    • Create one environment that demonstrates:

      • Deployment and configuration of a database, frontend, and backend.

      • Infrastructure provisioned via infrastructure-as-code.

      • Configuration management for consistency and idempotence.

      • CI/CD pipelines for build, deploy, and test.

      • Containerization and orchestration of services.

      • SSL termination with valid certificates.

      • Monitoring, logging, and observability.

      • AI-assisted exploration or validation of the solution.

      • Resource tagging:

        • env: dev

        • owner: [your_email_address]
