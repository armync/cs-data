1) Mental Model

Working Directory  --(git add)-->  Staging Area (Index)  --(git commit)-->  Local Repo (history)
       ^                         ^                                      ^
       |                         |                                      |
 (git restore)           (git restore --staged)                 (git reset --soft)
       |                         |                                      |
       └-------------------------(git reset <file>)----------------------┘

Local Repo  --(git push)-->  Remote Repo (origin)
Remote Repo --(git fetch)--> Local Repo (updates only)
Remote Repo --(git pull)-->  Local Repo (fetch + merge or rebase)
  • HEAD: the commit your working directory currently reflects.
  • Upstream/Tracking branch: remote branch linked to your local branch.
  • Modern: prefer git switch and git restore over legacy git checkout.

2) Creating a Repository

git init [project-name]        # initialize from scratch
git clone <url>                 # clone an existing remote repository

Tip: after git init, make at least one commit before pushing to a remote.

3) Inspect and Observe Changes

git status                      # show modified/staged/untracked files
git diff                        # show unstaged changes
git diff --staged               # staged (Index vs HEAD)
git diff HEAD                   # everything since last commit
git show <commit>[:file]         # commit details (optional single file)
git blame <file>                 # last modifier per line
git log                         # detailed history
git log -p [file|dir]            # history with diffs
git log --oneline --graph --decorate --all

Use git log --graph --oneline to visualize branch flow clearly.

4) Making Changes

# Stage and commit
git add <file>                   # stage specific files
git add .                        # stage all changes (tracked + untracked)
git commit -m "message"          # commit staged files
git commit -am "message"         # tracked files only (skips new files)

# Unstage or undo
git restore --staged <file>      # unstage (keep edits) — modern
git reset <file>                 # unstage — older
git restore <file>               # discard local edits (careful) — modern
git checkout -- <file>           # discard — older

# Resetting
git reset --soft  <commit>       # keep changes staged
git reset --mixed <commit>       # keep changes in working directory
git reset --hard  <commit>       # discard everything local

When in doubt, stash or branch before destructive actions.

5) Working with Branches

git branch                      # local branches
git branch -av                  # local + remote-tracking

# Create and switch
git switch -c <new-branch>      # modern (recommended)
git checkout -b <new-branch>    # older

# Switch branches
git switch <branch>             # modern
git checkout <branch>           # older

# Delete branches
git branch -d <branch>          # delete if merged
git branch -D <branch>          # force delete (unmerged)

# Merge and rebase
git merge <branch>              # merge target into current
git rebase <branch>             # replay current onto target

# Tagging
git tag v1.0.0
git tag -a v1.0.0 -m "Release 1.0.0"
git push origin v1.0.0
git push --tags

Merge preserves the real history; rebase keeps it linear (best before pushing).

6) Synchronizing with Remotes

git remote add origin <url>     # link local repo to remote

# Fetch and pull
git fetch                        # safe: update tracking refs only
git pull                         # fetch + merge (classic)
git pull --rebase                # fetch + rebase (modern)

# Push
git push                         # if upstream set
git push -u origin <branch>      # first push, sets upstream

Prefer git pull --rebase for your feature branches.

7) Common Workflows & Useful Recipes

git add -p <file>                # interactively stage chunks
git commit --amend               # modify last commit (message or content)
git revert <commit>              # safely undo (new commit)
git stash                        # stash tracked changes
git stash -u                     # include untracked files
git stash pop                    # reapply top stash
git fetch --prune                # delete remote-tracking refs that vanished

# Daily example flow
git fetch
git switch main
git pull --rebase

git switch -c feature/my-feature
git add -p
git commit -m "Add feature part 1"

git fetch
git rebase origin/main

git push -u origin feature/my-feature

git switch main
git pull --rebase
git branch -d feature/my-feature

8) Common Pitfalls and Recovery Tips

8.1 Local Changes Mistakes

# Accidentally committed wrong files (not pushed)
git reset --soft HEAD~1          # undo last commit, keep changes staged

# Discard edits in a file (careful)
git restore <file>               # replace with HEAD version

If you’ve already pushed the bad commit, use git revert <commit> to create a new commit that undoes it instead of rewriting shared history.

8.2 Branch & Merge Issues

# Merge conflicts
git status                       # see conflicted files
git add <file>                   # after manual conflict resolution
git merge --continue             # finish the merge
# or abort entirely
git merge --abort

# Committed on the wrong branch
git switch correct-branch
git cherry-pick <commit>         # copy commit onto the right branch
git switch wrong-branch
git reset --hard HEAD~n          # remove those commits from the wrong branch

Cherry-pick copies commits; the originals remain until you reset or revert them.

8.3 Remote & History Problems

# Force push mistake: restore previous ref
git reflog                        # find the good commit
git reset --hard <hash>
git push --force-with-lease       # restore without clobbering others

# Sync local with remote deletions
git fetch --prune

--force-with-lease refuses to overwrite changes if someone has updated the remote.

8.4 Recovery Tools

git stash push -m "backup"       # quick safety net
git branch backup-$(date +%s)     # save current HEAD to a branch
git restore --source=<commit> <path>   # restore a file from any commit
git log --oneline --graph --decorate --all   # visualize and locate commits

When unsure, branch or stash first—then experiment safely.

9) Glossary

  • Working Directory (WD): your actual files.
  • Staging Area (Index): snapshot ready for the next commit.
  • HEAD: pointer to the current commit.
  • Branch: movable pointer to a line of commits.
  • Remote: external repository (e.g., GitHub).
  • Rebase: reapply commits on another base.
  • Merge Commit: commit combining two histories.
  • Fast-forward: pointer move without a merge commit.
  • Detached HEAD: state when not on a branch.
