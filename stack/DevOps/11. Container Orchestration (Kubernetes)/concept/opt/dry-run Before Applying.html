Why Every K8s Dev Should Use dry-run Before Applying Anything

Don't let a broken YAML break your cluster. Learn how to validate like a pro using --dry-run. Preview before you deploy!

1. What is --dry-run?

The --dry-run flag is used to validate and preview Kubernetes commands without actually applying changes to the cluster. It's a safety measure to verify if your YAML or command is correctly structured and valid.

2. Types of --dry-run Flags

--dry-run without any value defaults to --dry-run=client in newer Kubernetes versions.

3. Examples of Using --dry-run

Checking if YAML File is Valid

kubectl apply -f pod.yaml --dry-run=client
  • Checks syntax and structure locally without hitting the API server.
  • Won't detect if the image exists or if the Pod can be scheduled.

Creating a Pod Imperatively (Dry Run Mode)

kubectl run mypod --image=nginx --dry-run=client -o yaml
  • Returns the generated YAML file without creating the Pod.
  • Useful for generating YAML templates for later use.

Validating Against the API Server (More Strict)

kubectl apply -f pod.yaml --dry-run=server
  • Checks with the Kubernetes API server to ensure the YAML file is valid and would be accepted.
  • Does not create the resource but verifies if it's deployable.

Generating YAML Files Using --dry-run

kubectl run mypod --image=nginx --dry-run=client -o yaml > mypod.yaml
  • Generates a YAML file without creating the pod, saving it for later modification or application.

4. Why Use --dry-run?

  • Testing & Validation: Ensure your resources are correctly defined before deployment.
  • Template Generation: Create YAML templates quickly for future use.
  • Safety Measure: Avoid accidental changes to a live cluster.

Summary

  • The --dry-run flag is a great way to test commands without making actual changes.
  • It helps avoid mistakes and allows you to generate YAML files for further editing.
